{% load asset_filters %} {% comment %} Player drill-down asset table. Adapted from (not a verbatim include of) anthias_server/app/templates/_asset_table.html / _asset_row.html: those hardcode `{% url 'anthias_app:...' %}` calls with no player_id parameter, which can't resolve for a route family that's scoped under players//assets/... here — so a verbatim reuse wasn't possible without generalising the shared player templates (risking a regression there). This file mirrors their markup/CSS classes/Alpine structure closely and reuses the *same* asset_filters template filters (schedule_pills, schedule_window, humanize_duration) and Asset.is_active()/ get_play_days() methods — both work unchanged against the transient (unsaved) Asset instances adapters.asset_from_player_dict builds from the player's JSON, since they're plain attribute/getattr reads. Unlike the player app's own 5s poll (cheap local DB read), every poll of this partial makes a live outbound HTTP call to the actual player (PlayerAPIClient.list_assets()) — a slower ~15s interval keeps that reasonable. {% endcomment %}
